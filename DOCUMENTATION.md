## 1. Project Overview
NutriTech is a modular agricultural monitoring system designed to track soil and environmental telemetry from various "tubs" (growing buckets). The project consists of a **Python/Flask Backend** and a **React/Vite Frontend**, all integrated with **Supabase** for data persistence and real-time updates.

---

## 2. Architecture

### 📡 Data Flow
1. **Sensors (RPI/Hardware)**: Collect soil moisture, pH, temperature, etc., and push data directly to Supabase `public.sensor_data`.
2. **Supabase**: Acts as the central data hub. It uses multiple schemas:
   - `public`: Hardware status and raw sensor logs.
   - `experiment`: Metadata about tubs, experiment configurations, and mapping.
   - `ml`: Processed data and health scores generated by machine learning models.
3. **Backend (Flask)**:
   - Acts as an API proxy for the frontend.
   - Manages complex joins (e.g., getting experiments with their associated tubs).
   - Serves the built frontend in production.
4. **Frontend (React)**:
   - Provides a rich, interactive dashboard for real-time monitoring.
   - Includes anomaly detection charts and health score visualizations.

---

## 3. Detailed File Breakdown

### 📂 Backend (`/backend`)
- **`app.py`**: The entry point. Initializes the Flask app, registers API routes (blueprints), and configures CORS. It also serves the frontend build files.
- **`routes/tubs.py`**: Handles API endpoints for fetching tub information (`/api/tubs/`) and specific tub configurations.
- **`routes/experiments.py`**: Manages experiment data. It performs lookups to find which buckets are currently assigned to which experiment.
- **`services/supabase_service.py`**: A helper module that initializes the Python Supabase client using environment variables.

### 📂 Frontend (`/frontend/nutritech-dashboard`)
- **`src/App.jsx`**: The main router. It defines the navigation structure (Home, Analytics, Experiments).
- **`src/pages/Home.jsx`**: The primary dashboard view. It fetches live telemetry using `dataQueries.js` and displays a grid of "Tub Cards" with health and risk indicators.
- **`src/services/dataQueries.js`**: A vital utility that handles the "multi-schema" nature of the database. Since tables move between `public` and `experiment`, this service tries multiple schemas until it finds the data.
- **`src/services/supabaseClient.js`**: Initializes the JavaScript Supabase client for the frontend.
- **`src/components/Layout.jsx`**: The site wrapper containing the header, navigation, and "System Online" status indicator.

## 4. What Must Need to be Done (Roadmap)

### 🛠️ Short Term
1. **Model Integration**: The "Predict" buttons on the UI are currently non-functional. The backend needs to integrate with actual ML models to replace the simulated risk/health scores.
2. **Authentication**: Implement a login system to protect the dashboard and prevent unauthorized access to experimental data.
3. **Alerting System**: Configure Supabase Functions or a backend worker to send notifications (Email/SMS) when sensor readings exceed safety thresholds (e.g., soil moisture < 20%).

### 🚀 Long Term
1. **Historical Comparison**: Add a feature to compare current growth rates against previous successful experiments.
2. **Offline Data Sync**: Enhance the hardware ingest logic to cache sensor data locally if the internet connection is lost and sync later.
3. **Advanced Calibration**: Implement a UI for calibrating individual sensor offsets (pH and EC sensors often drift).

## 5. Environment Setup
Create a `.env` file in both `backend` and `frontend/nutritech-dashboard` with the following:
```env
SUPABASE_URL=your_project_url
SUPABASE_KEY=your_service_role_or_anon_key
```

### Running Locally
1. **Backend**: `python -m flask run`
2. **Frontend**: `npm run dev` in the frontend directory.
